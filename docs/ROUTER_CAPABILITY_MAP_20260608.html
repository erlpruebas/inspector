Inspector · Especificación del router

Mapa de capacidades y rutas

Una ruta por herramienta. Cada petición se descompone en ingredientes, acciones operativas, carga cognitiva y garantías verificables. Después se selecciona la herramienta compatible con menor latencia demostrada.

21rutas E0-E20
24acciones comprobables
25tareas HITL principales
34pruebas del orquestador

Convención de voz: cuando la transcripción escriba Rock, Grok o “Compon”, aquí se interpreta como Groq y Compound, salvo que se cite expresamente Grok de xAI.

Principio de selección

Preparar los datos, filtrar por capacidades reales, elegir la ruta más rápida, comprobar el resultado y escalar únicamente cuando falla una garantía objetiva.

01 · MODELO DE TAREA

Qué debe detectar el router

“Difícil” no es una característica suficiente. El router debe describir qué información falta, qué debe tocar la herramienta, qué razonamiento hace falta y qué debe comprobarse al terminar.

A

Ingredientes previos

Memoria, conversación, archivos, calendario, contactos, web o datos preparados.

B

Acceso instrumental

Texto, web, PDF, Excel, imagen, audio, ZIP, carpetas, código o escritura de archivos.

C

Trabajo cognitivo

Extraer, sintetizar, comparar, calcular, diagnosticar, planificar o verificar.

D

Garantías

Exactitud, actualidad, fuentes, archivo creado, resultado verificado o confirmación humana.

02 · CAPACIDADES

Qué debe poder hacer la herramienta

Son acciones observables. Para cada herramienta deben marcarse como directas, posibles con datos preparados o no soportadas.

01

Recuperar un dato de memoria

Localizar una fecha, dirección, código, contacto o importe concreto.

02

Recuperar varias piezas

Traer varios apuntes relacionados y entregarlos como contexto preparado.

03

Leer conversación reciente

Usar mensajes anteriores necesarios para completar la petición actual.

04

Localizar archivos

Encontrar archivos por nombre, tipo, carpeta, fecha o contenido aproximado.

05

Leer archivos de texto

Abrir Markdown, TXT, CSV, JSON, logs o código fuente.

06

Leer PDF o documentos

Extraer texto, tablas, cláusulas y estructura de documentos binarios.

07

Trabajar con hojas de cálculo

Abrir Excel, filtrar filas, cruzar tablas, calcular y conservar fórmulas.

08

Leer imágenes

Interpretar fotografías, tickets, capturas, diagramas o documentos escaneados.

09

Leer o transcribir audio

Convertir audio en información utilizable y extraer datos relevantes.

10

Abrir archivos comprimidos

Inspeccionar ZIP, localizar el archivo válido y operar con su contenido.

11

Manejar varios archivos completos

Leer y cruzar documentos sin reducirlos previamente a un único fragmento.

12

Hacer una búsqueda web

Obtener un dato actual mediante una consulta o una llamada de herramienta.

13

Hacer varias búsquedas web

Consultar varias páginas o fuentes y reunir los resultados.

14

Compilar investigación con fuentes

Comparar fuentes, resolver discrepancias y aportar referencias trazables.

15

Calcular con datos estructurados

Filtrar, sumar, reconciliar, calcular porcentajes y aplicar restricciones.

16

Ejecutar código o comandos

Usar terminal, scripts y herramientas para obtener o verificar resultados.

17

Crear archivos

Generar informes, tablas, documentos, código u otros artefactos persistentes.

18

Modificar archivos existentes

Editar contenido real sin limitarse a proponer texto en la respuesta.

19

Conservar formato

Mantener estructura, fórmulas, estilos y convenciones del archivo original.

20

Manejar contexto largo

Trabajar con mucha información sin perder hechos o relaciones importantes.

21

Sintetizar y redactar

Convertir datos preparados en una respuesta, resumen, correo o propuesta útil.

22

Comparar y razonar

Elegir entre opciones, cumplir restricciones y diagnosticar causas.

23

Detectar información ausente

Parar y preguntar cuando faltan datos obligatorios para actuar.

24

Verificar el resultado

Comprobar cifras, fuentes, pruebas, formato y existencia del artefacto final.

05 · APRENDIZAJE

Router evolutivo con experiencias

El sistema aprende por forma de tarea y capacidad operativa. No asigna una nota única y permanente a cada modelo.

1 · DescribirEtiquetar acciones, accesos y carga cognitiva
2 · ExplorarProbar ruta actual y desafiantes en modo evaluación
3 · ComprobarValidar cifras, claves, fuentes, archivos y pruebas
4 · JuzgarGemini y Codex 5.5 puntúan respuestas anonimizadas
5 · AprenderActualizar éxito, calidad, latencia y confianza
A

Experiencia granular

Se guarda herramienta × capacidades × forma de tarea, además de versión, tiempo y causa de fallo.

B

Objetivo antes que juez

Una cifra incorrecta, un archivo inexistente o una prueba fallida no se arreglan con una buena nota de estilo.

C

Promoción con confianza

Un desafiante necesita al menos diez muestras, 80 % de éxito objetivo y 7/10 de calidad para optar a la ruta principal.

D

Desacuerdo conservador

Si los jueces discrepan, se mantiene la ruta actual y se acumulan más pruebas; no se aprende de una sola opinión.

La exploración debe ejecutarse con tareas sintéticas, reproducibles o en un modo de evaluación explícito. No conviene duplicar silenciosamente todas las peticiones reales del usuario.

Cómo se elige y escala

La selección final es determinista. El LLM rápido describe la tarea; el programa decide qué ruta cumple el contrato.
